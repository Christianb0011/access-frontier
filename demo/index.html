A new hire waited three weeks for access.
The ticket queue was the reason.

Access requests are the most common IT ticket. Each one is policy-sensitive: the wrong grant is a security incident, a slow one is a stalled employee. We built an open model + deterministic guard that resolves them safely — and a frozen benchmark that proves it.

Grounded in real tickets. 2,229 anonymized IT-support tickets (tasksource/it-support-tickets) → 1,960 English → 1,148 access-related → the request patterns our benchmark is built on:

Results on the frozen benchmark

Strict raw score shown (exact JSON contract). Normalized scores (prose-wrapped JSON accepted): GLM-5.3 (frontier) 99.5% · Kimi K3 (frontier) 99.5% · GLM-5.3 Flash base 99.5% · Flash base + guard 99.5%. Kimi K3 price not pinned. Pending: Flash SFT, Flash SFT + guard (AccessFrontier)

What we found

  • 99.0% strict on the main benchmark and 99.0% on the hard set with zero unsafe actions — from a model ~9× cheaper than the frontier (GLM-5.3: 90.5% / 81.9%, 3 unsafe executions).
  • The agentic guard turns a cheap model into a reliable one: Flash base 96.0% → 99.0% (main), 95.2% → 99.0% (hard) — missing lookups completed, policy-violating writes blocked and logged, JSON contract enforced.
  • The best finding: frontier models reach the right final state while still executing unauthorized writes along the way (grant-then-regret, wrong identity). State-only benchmarks miss it; ours scores the trajectory — and the guard makes those writes impossible.
